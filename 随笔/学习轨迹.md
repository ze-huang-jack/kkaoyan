> 本文由 Claude Code 于 2026-10-11 从 git 提交历史中还原，数据来源为 `kkaoyan` 仓库的全部 66 次提交。

## 一、还原方法（以及它的局限）

从提交历史能读到三类信号，可靠度递减：

| 信号          | 含义           | 可靠度                    |
| ----------- | ------------ | ---------------------- |
| 新增 `.md` 文件 | 当天开了一个新主题    | 高                      |
| 修改 `.md` 文件 | 回头深化/复盘了某个主题 | 高                      |
| 新增图片数量      | ≈ 当天做的题量     | **中**（截图≠全是题，且批量导入会污染） |

**已知的两个"污染点"，看数据时必须扣掉：**

- **2026-08-05**：一次性导入 120 篇存量笔记 + 66 张图（原因见下节）
- **2026-09-24**：一天 5 次提交，含大量文件重命名，git 把改名误算成了新增（448 张图是假的）

另外，git 只能记录"笔记被保存的时候"，不能记录"知识被理解的时候"。

## 五、怎么重新生成

在仓库根目录执行（需要 `python3`）：

```bash
git -c core.quotepath=false log --reverse \
    --format='=== %h | %ad | %s' --date=format:'%Y-%m-%d' \
    --name-status
```

这会按时间顺序列出每次提交改动的文件。要统计的话，按日期聚合 `A`（新增）/ `M`（修改）状态的 `.md` 文件，并累计 `A` 状态的图片数。

**建议每 2-3 个月重跑一次**，尤其是每个阶段结束时。这张表能看出：
- 哪个科目停滞了（阶段三的教训）
- 哪些笔记在被反复修改（= 还没吃透）
- 学习节奏的变化
