## 三、五个发现

### 1. 实际顺序不是教材顺序

**教材**：绪论 → 线性表 → 栈队列串 → 树 → 图 → 查找 → 排序

**实际**：绪论 → 线性表 → 栈队列数组 → **树** → **图** → **查找** → **排序** → ⏸️ 8天 → **串/KMP + 红黑树**

串是 9-08 建的 30 行空壳，一直空着，等到 9-24（排序都做完 8 天了）才回头把 KMP 填进去。

这不是错误，但暴露了一个模式：**倾向先做「有感觉」的，把最抽象的（KMP 的 next 数组）往后拖。**

### 2. 一天冲完排序，但尾巴硬啃了 10 天

9-16 分三次提交加了 291 行，一天干完排序主体（插入、交换、选择、归并、基数）。

然后卡住了。9-19 记录：

> 怎么数据结构的最后两节也变得这么难了 / 这个九大排序算法的比较 还有 外部算法，感觉就没学过一样，难死了o(╥﹏╥)o
>
> —— [[2026-09-19 艰难不平衡孤独的生活方式]]

从 9-16 卡到 9-26，整整 10 天，最后单日 +265 行收尾（排序比较 + 外部排序），当天宣布一轮完结。

**排序主体用 1 天，排序的「比较与应用」用了 10 天。** 擅长「学会一个算法」，吃力的是「横向比较九个算法」——这个比例值得记住。

## 五、怎么重新生成

在仓库根目录执行：

```bash
git -c core.quotepath=false log --reverse \
    --format='=== %h | %ad | %s' --date=format:'%Y-%m-%d' \
    --numstat -- '408/01_data_structures_and_algorithm/' \
    '04专业课408/01_data_structures_and_algorithm/'
```

`--numstat` 会给出每次提交的增删行数，按日期聚合即可还原「每天投入多少、改了哪章」。

注意要同时传**新旧两个路径**——9-24 有一次目录改名，只传新路径会丢掉前半段历史。
