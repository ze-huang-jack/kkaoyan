DMA控制器内有4类寄存器：
1. 命令寄存器
2. 内存地址寄存器
3. 数据寄存器
4. 数据计数器

- **命令寄存器** —— **干什么**（读/写、启动等）
- **内存地址寄存器** —— **放哪里**（内存地址）
- **数据寄存器** —— **当前搬什么**（临时中转数据）
- **数据计数器** —— **还剩多少**（传输长度，减到0结束）


| 问题                    | 标准答案            |
| --------------------- | --------------- |
| 预处理运行在哪？              | **内核态**         |
| 后处理运行在哪？              | **内核态（中断服务程序）** |
| 预处理时请求I/O进程状态？        | **运行态（内核态执行）**  |
| DMA传输期间请求I/O进程状态？     | **阻塞态**         |
| 后处理开始时请求I/O进程状态？      | **阻塞态**         |
| 后处理结束后请求I/O进程状态？      | **就绪态**         |
| "预处理和后处理都是请求I/O进程执行的" | **错误**          |

### IO软件层次结构

| 层次       | 主要功能                 | 关键词                               |
| -------- | -------------------- | --------------------------------- |
| 用户层I/O软件 | 给用户提供IO接口            | 库函数、系统调用、SPOOLing                 |
| 设备独立性软件  | 屏蔽设备差异               | 统一接口、设备的分配与回收、设备保护、缓冲管理、差错控制、设备命名 |
| 设备驱动程序   | 把OS命令翻译成设备命令，操作设备控制器 | 翻译命令、通过IO接口控制设备（控制寄存器）            |
| 中断处理程序   | 响应设备完成中断             | 保存现场、处理中断、唤醒进程                    |
| I/O硬件    | 真正完成数据传输、执行I/O操作     | 控制器、DMA、设备                        |

将系统调用参数翻译成设备操作命令是由设备独立性软件完成的
设备独立性软件把系统调用参数（如 fd 缓冲区地址、读写长度等）转换成统一的设备请求（例如读取磁盘逻辑块100）
而设备驱动程序再把这个统一的设备请求转化成具体设备控制器能够执行的硬件命令（比如写寄存器、设置 DMA 发送 read 命令等）

### 缓冲的计算

T, M和C分别对应IO设备输入到内核缓冲区、CPU把数据从内核缓冲区搬到用户工作区(用户缓冲区)、CPU处理/计算的时间
那么双缓冲处理每块数据的时间为$$Max(T, C+M)$$因为IO设备和CPU可以并行工作

单缓冲处理每块数据的时间为$$Max(T, C) +M$$
复制数据的时候CPU必须等待


单缓冲：$(T+M) \times N+C$
双缓冲：$T \times N+M+C$ 
（N是要处理的数据块的总数）



### 磁盘调度算法

| 算法                             | 名字       | 思想                         | 优点                     | 缺点                 |
| ------------------------------ | -------- | -------------------------- | ---------------------- | ------------------ |
| FCFS(First Come First Serve)   | 先来先服务    | 按请求顺序                      | 公平简单                   | 寻道时间长              |
| SSTF(Shortest Seek Time First) | 最短寻道时间优先 | 离磁头最近优先                    | 优于FCFC                 | 可能饥饿               |
| SCAN                           | 扫描算法     | 电梯，左右往返                    | 寻道性能好，避免饥饿             | 两端磁道请求等待久          |
| C-SCAN                         | 循环扫描     | 单方向循环（返回时快速移动至起始段且不处理任何请求） | 消除了对磁道两端的不公平性，等待更均匀    | 磁头总是严格地从磁盘一端移动到另一端 |
| LOOK调度                         |          | SCAN优化，不到边界                | 磁头只需移动到当前方向上最远请求位置即可返回 |                    |
| C-LOOK调度                       |          | C-SCAN优化                   |                        |                    |
