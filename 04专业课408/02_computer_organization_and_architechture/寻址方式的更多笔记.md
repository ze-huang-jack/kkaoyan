
整个寻址方式这一节的主线是：
一条指令里给出的“地址/数字”，CPU 到底需要经过几步，才能找到真正要操作的数据

先看，假设有一条指令：
```
LOAD R1, 100
```
这里的 100 ，可能代表三种不同的概念：

①指令中的地址字段（形式地址）
就是指令里直接写出来的那个东西，如 100
（可以是**间接寻址**，比如 内存\[100]=200，内存\[200\]=300, 这里 300 是操作数，200是 EA）

②有效地址 EA
CPU 最终算出的”真正的数据地址“，这时 100 时 EA 的话，那么内存\[100\]=200，这个 200 是操作数
（这种一般可以是**寄存器间接寻址**吧，寄存器里存着的就是 EA。还有可能是别的寻址方式吧，肯定还有我认为 TODO）

③操作数
这种情况就是立即寻址方式了吧，指令的 100 本身就是操作数，不需要去内存里面找

所以：
指令里的数字->根据不同的寻址方式解释 -> 得到有效地址 EA -> 根据 EA 去内存里找操作数
但是有些寻址方式不需要去内存找，比如立即寻址、寄存器寻址
（寄存器里的就是操作数，跟寄存器间接寻址的区别是，后者里存着的是 EA，而不是操作数）

|寻址方式|指令里的东西代表什么|是否需要访存找操作数|
|---|---|---|
|立即寻址|操作数本身|❌|
|直接寻址|操作数所在地址|✅|
|间接寻址|一个“地址的地址”|✅✅|
|寄存器寻址|操作数所在寄存器|❌|
|寄存器间接寻址|寄存器中存放的地址|✅|
|基址寻址|基址寄存器 + 偏移量|✅|
|变址寻址|变址寄存器 + 偏移量|✅|
|相对寻址|PC + 偏移量|✅|
这些寻址方式的区别，本质上就是“指令中的那个字段到底是什么意思”

基址寻址：基址寄存器负责”我在哪一片区域“，偏移值负责”这片区域的第几个“
比如：BR=1000，指令里有 20，
那么 EA=BR+20=1020
再访问 M\[1020\] = 操作数

变址 IX 寻址：
经典应用是数组访问
假设数组首地址=1000
变址寄存器 R=3
那么 EA=1000+3 × 元素大小
然后 M\[EA\]
适合遍历数组、循环访问数据

所以基址寻址和变址寻址有什么区别呢？？

基址寻址：EA=基址寄存器+偏移量
(这里基址寄存器里的可以是数组的首地址，偏移量是数组的第几个元素的地址相对首地址的偏移量，当然数组只是其中一个例子)
准确的说，BR=这一块程序/数据所在的起始地址，偏移量 A=目标数据相对于这个起始位置的偏移量

变址寻址：EA=变址寄存器+偏移量
这里的偏移量可以理解为数组首地址，变址寄存器 IX(IndeX register) 里存的是数组的下标 i
offset A = 数组首地址，IX = i × 元素大小

通常，基址通常相对稳定，所以**基址寄存器不怎么变化**
而**变址寄存器经常不断变化**，所以适合数组、循环、遍历

相对寻址：PC + 偏移量
例如 PC=1000
指令中的偏移量 +200
那么 EA=PC+200=1200
CPU 就跳到 1200

CPU 执行一条指令，可以粗略看成：
取指令（M\[PC]=IR, 取指要**访问内存**，把当前执行指令暂存到 IR 指令寄存器里）-> 分析指令（控制器中的指令译码逻辑对 IR 中的指令进行译码，并据此产生相应控制信号）->找操作数 -> 执行（执行 = 按照这条指令要求，真正完成它规定的操作）

 
 如果是那些相对寻址、基址寻址、变址寻址，这些情况的指令一般长什么样子：

LOAD R1, 30(RB)      ← 基址寻址
LOAD R1, 1000(RI)    ← 变址寻址
JMP  +200            ← 相对寻址 从当前 PC 的位置向前跳 200
