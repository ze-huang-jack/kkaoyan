### 用户可见寄存器和用户不可见寄存器
可见：PC、GPRs、专用地址寄存器(变址、基址、堆栈指针)、FR(标志寄存器/只读型用户可见寄存器)
不可见(透明)：MAR、MDR、IR、页表基址寄存器
### 机器字长与ALU和寄存器的位数(宽度)
机器字长(Machine Word Length)是指CPU一次能直接处理的二进制数据的位数。我们平时说的“32位CPU”或“64位CPU”，这里32和64指的就是机器字长。

机器字长由CPU的指令集架构(ISA)设计决定，并在硬件成面由ALU的算数逻辑处理能力和通用寄存器的容量大小共同体现。
#### 一定与机器字长相同的部件
- ALU
- 通用寄存器
#### 不一定与机器字长相同的部件
- 指令寄存器（IR）
	- 由指令字长决定，而非机器字长
- 浮点寄存器（FPR）
	- 由浮点精度标准（如IEEE 754）决定
- 程序计数器（PC）和存储器地址寄存器（MAR）
	- 由 CPU的物理/虚拟寻址空间（[[地址总线宽度]]）决定

### CPU 内部寄存器

| 寄存器                                              | 干什么               |
| ------------------------------------------------ | ----------------- |
| PC(Program Counter)                              | 放下一条要执行的指令的地址     |
| IR(Instruction Reg)                              | 放当前正在执行的指令本身，不是地址 |
| MAR(Memory Address Reg)                          | 放要访问的主存地址         |
| MDR(Memory Data Reg)                             | 放与主存交换的数据         |
| ACC(Accumulator)                                 | 累加器，某些 CPU 中用于运算  |
| 通用寄存器 GPRs                                       | 保存操作数、地址、中间结果     |

比如 CPU 要取指：

**MAR ← PC**

MAR = 1000H
然后访问主存：
**MDR ← M\[MAR]**
然后：
**IR ← MDR**
最后：

### 汇编程序员可见的寄存器、不可见的寄存器

PC 可见：
`JMP 1000H`, `CAll 1000H`,这些指令可以间接地改变 PC，对程序员是可见的
可见的还有：通用寄存器、基址寄存器、变址寄存器、PC、堆栈指针、状态寄存器（半可见）

不可见的有：**MAR、MDR、IR**

### CPU 内部组成与机器字长
| 部件        | 里面存什么         | 通常与机器字长关系                        |
| --------- | ------------- | -------------------------------- |
| 通用寄存器 GPR | 数据、地址等        | **通常 = 机器字长**                    |
| PC        | 指令地址          | **通常 = 地址总线/地址空间所需位数，不一定等于机器字长** |
| MAR       | 主存地址          | **通常 = 地址线宽度，不一定等于机器字长**         |
| MDR       | 主存与 CPU 交换的数据 | **通常与数据总线宽度有关，不一定等于机器字长**        |
| IR        | 当前指令          | **通常 = 指令字长，不一定等于机器字长**          |
| ALU       | 运算数据          | **通常与机器字长相同或相近**                 |
| 标志寄存器     | ZF、CF、OF 等    | **通常远小于机器字长**                    |

数据看机器字长，地址看地址宽度，指令看指令长度，状态看状态位数

基本上只有 **ALU** 和**通用寄存器**跟机器字长相同

## 2 . 指令执行过程
CPU 执行一条指令，不是一个动作，而是一连串微操作

取指周期、间址周期、执行周期、中断周期
(当然，不是每条指令都有所有周期)

**机器指令**
↓ 拆成
**一系列微操作**
↓ 由
**控制信号**
↓ 驱动
**数据通路**

### 单周期、多周期、流水线处理器
#### 单周期处理器：一条指令，一个周期
所以指令都必须在一个时钟周期内完成，而且所有指令的时钟周期一样长。时钟周期必须足够长，长到能容纳“最慢的那条指令”
比如
add 指令 5ns
load 指令 10ns
那么整个 CPU 的时钟周期至少是 10ns

#### 多周期处理器：一条指令，多个周期
不同指令可以使用不同数量的时钟周期
这样就不需要为了最慢的指令，让所有指令等那么久

#### 流水线处理器：多条指令同时干
多周期处理器虽然把一条指令拆开了，但是通常是：一条指令干完，再处理下一条
但流水线则是：把不同指令放进不同阶段，同时处理
例如：
把指令拆成 5 个阶段：
```
IF → ID → EX → MEM → WB
取指   译码   执行   访存   写回
```
现在假设有 4 条指令：
```
周期       1      2      3      4      5      6      7

指令1     IF     ID     EX     MEM    WB
指令2            IF     ID     EX     MEM    WB
指令3                   IF     ID     EX     MEM    WB
指令4                          IF     ID     EX     MEM    WB
```
第一条指令在执行阶段的时候，第二条指令已经在译码了，第三条指令已经在取指了。

一条指令仍然需要经过 5 个阶段，但 CPU 不再傻等着第一条做完才开始第二条


#### 三类处理器指令执行模型比较：

|            | 单周期       | 多周期    | 流水线         |
| ---------- | --------- | ------ | ----------- |
| 一条指令       | 1个周期完成    | 多个周期完成 | 多个阶段完成      |
| 多条指令能否同时进行 | ❌         | 一般❌    | ✅           |
| 时钟周期       | 较长        | 较短     | 较短          |
| 硬件利用率      | 较低        | 较高     | 高           |
| 设计复杂度      | 简单        | 中等     | 高           |
| 主要问题       | 周期被最慢指令拖长 | CPI 较高 | 冒险、暂停、冲刷流水线 |

## 3 . 数据通路
时序逻辑元件和组合逻辑元件是数据通路的基本构件
两者的区别是：
**这个东西能不能把数据自己记住？**
能记住，就是时序逻辑元件
不能记住，只能根据当前输入立刻产生输出，就是组合逻辑原元件

所以通用寄存器 R0、R1...这些都是时序逻辑原件
ALU 是组合逻辑原件

### 常见的组合逻辑电路：

| 元件        | 干什么           |
| --------- | ------------- |
| ALU       | 算术、逻辑运算       |
| 加法器       | 加法            |
| MUX 多路选择器 | 从多个输入中选择一个    |
| 译码器       | 根据输入编码选择对应输出  |
| 三态门       | 控制某条线路是否向总线输出 |
#### MUX 多路选择器
现在有 4 个输入：A, B, C, D，但输出只有一个
MUX 可以根据控制信号：
00 → 选 A  
01 → 选 B  
10 → 选 C  
11 → 选 D
于是：
四选一 MUX
本质就是：
**从多个输入中选一个送出去。**

#### 三态门
三态门有三个转态：0、1和高阻态 Z
用来“允许/禁止某个部件向公共总线输出数据的开关”


> **MUX：多个输入，选一个。**

> **三态门：多个输出，控制谁能输出。**

MUX：
多个东西 → MUX → 一个地方

三态门：
一个东西 → 三态门 → 总线

### 数据通路的组织和划分
三种：
CPU 内部单总线
CPU 内部多总线
专用数据通路

#### CPU 内部单总线
所有的部件连接到同一条公共总线
例如：
PC -> Bus -> MAR
MDR -> Bus -> IR
R1 -> Bus -> Y

#### 多总线结构
R1 -> BusA -> ALU
R2 -> BusB -> ALU
ALU -> BusC -> R3
多总线的核心思想：用更多硬件换更高的数据传输并行度
代价就是线路复杂、硬件成本增加

#### 专用数据通路
它的优点：
> 路径专门设计，冲突少，效率高。

缺点：
> **线路特别多，硬件复杂。**


|结构|核心思想|优点|缺点|
|---|---|---|---|
|单总线|大家共用一条路|简单、便宜|冲突多、慢|
|多总线|大家共用几条路|并行性更高|更复杂|
|专用数据通路|每种数据流都有专门线路|快、冲突少|硬件最多、最复杂|
注意：数据通路是指 CPU 内部总线，是 CPU 内部各个部件之间的数据传输
比如：PC -> CPU 内部总线 -> MAR

跟系统总线是不一样的，它是：
CPU ↔ 主存  
CPU ↔ I/O

它解决的问题是：
CPU 正在执行程序的时候，如果突然发生一个需要处理的事件怎么办？

例如：
键盘输入来了

CPU 不需要一直傻等，而是：
正常执行程序
↓

↓

↓
保存现场
↓

中断 Interrupt，外部事件，通常与当前指令无直接关系，例如：时钟中断、I/O设备完成操作、网卡收到数据

- 异常：CPU 执行当前指令时，发现了问题或特殊情况。    
- 外部中断：CPU 外部有事件需要处理

## 6. 指令流水线

一条指令可能有：
取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB
如果没有流水线：
第一条：IF → ID → EX → MEM → WB
全部做完以后，第二条才开始。但是流水线：第一条做 ID 的时候，第二条可以做 IF。
于是：
第一条 EX
第二条 ID
第三条 IF
可以同时进行。

流水线的本质：
不同指令处于不同流水段，所以多个流水段在同一个时钟周期同时工作
把一条指令的执行过程划分成多个阶段，使不同指令的不同阶段在时间上重叠
### 流水线的 3 个重要问题：冒险
1. 结构冒险
硬件资源可能不够，比如两条指令想同时访问同一个存储器
2. 数据冒险
后面的指令可能需要前面指令的结果，但是前面的结果还没有产生（更准确的是：后面的指令依赖前面指令产生的数据，而前面的指令尚未把该数据写入后续阶段需要的位置）
比如：
`ADD R1, R2`
`SUB R3, R1`
第二条指令需要 R1，但是第一条还没写回，这就是数据冒险
3. 控制冒险
例如：
`beq` CPU 不知道到底：继续执行下一条，还是跳到另外一个地址。这就是控制冒险

结构冒险=资源冲突
数据冒险=数据依赖
控制冒险=分支跳转

### 流水线的性能计算

流水线主要提高吞吐率，而不是简单地减少单条指令的执行时间
假设：
5 个阶段，每阶段 1 个时钟周期
非流水：
5 条指令：5 × 5 = 25 个时钟周期
流水线：
第一条需要 5 个周期进入流水线，之后基本每个周期完成一条
所以 5 条大概需要：5+4=9个周期

一般形式：
**k 个阶段，n 条指令**
理想情况下：
**k + n - 1 个时钟周期**
