### 用户可见寄存器和用户不可见寄存器
可见：PC、GPRs、专用地址寄存器(变址、基址、堆栈指针)、FR(标志寄存器/只读型用户可见寄存器)
不可见(透明)：MAR、MDR、IR、页表基址寄存器
### 机器字长与ALU和寄存器的位数(宽度)
机器字长(Machine Word Length)是指CPU一次能直接处理的二进制数据的位数。我们平时说的“32位CPU”或“64位CPU”，这里32和64指的就是机器字长。

机器字长由CPU的指令集架构(ISA)设计决定，并在硬件成面由ALU的算数逻辑处理能力和通用寄存器的容量大小共同体现。
#### 一定与机器字长相同的部件
- ALU
- 通用寄存器
#### 不一定与机器字长相同的部件
- 指令寄存器（IR）
	- 由指令字长决定，而非机器字长
- 浮点寄存器（FPR）
	- 由浮点精度标准（如IEEE 754）决定
- 程序计数器（PC）和存储器地址寄存器（MAR）
	- 由 CPU的物理/虚拟寻址空间（[[地址总线宽度]]）决定

## CPU 的基本组成
CPU=运算器+控制器+寄存器

运算器就是 ALU（算术逻辑单元，Arithmetic Logic Unit，专门负责加减、与或非、移位、比较、产生标志位

控制器本身**通常不负责计算数据**，它负责**根据当前指令，产生控制信号，让 CPU 各个部件按照正确的顺序工作**

ALU = 干活的人

### CPU 内部寄存器

| 寄存器                                              | 干什么               |
| ------------------------------------------------ | ----------------- |
| PC(Program Counter)                              | 放下一条要执行的指令的地址     |
| IR(Instruction Reg)                              | 放当前正在执行的指令本身，不是地址 |
| MAR(Memory Address Reg)                          | 放要访问的主存地址         |
| MDR(Memory Data Reg)                             | 放与主存交换的数据         |
| ACC(Accumulator)                                 | 累加器，某些 CPU 中用于运算  |
| 通用寄存器 GPRs                                       | 保存操作数、地址、中间结果     |
| FR 标志寄存器（PSWR，Program Status Word Reg, 程序状态字寄存器) | 保存程序状态/标志信息       |

比如 CPU 要取指：
PC = 1000H
那么：
**MAR ← PC**
于是：
MAR = 1000H
然后访问主存：
**MDR ← M\[MAR]**
然后：
**IR ← MDR**
最后：
**PC ← PC + 指令长度**

### 汇编程序员可见的寄存器、不可见的寄存器
“寄存器是不是在 CPU 内部” 跟 “汇编程序员是否可见” 是两回事

寄存器可不可见是在说：汇编语言程序员能不能通过 ISA 规定的机器指令，直接访问、读写这个寄存器。**ISA 有没有把这个寄存器作为程序员可以使用的编程接口暴露出来**

PC 可见：
`JMP 1000H`, `CAll 1000H`,这些指令可以间接地改变 PC，对程序员是可见的
可见的还有：通用寄存器、基址寄存器、变址寄存器、PC、堆栈指针

不可见的有：**MAR、MDR、IR**

### CPU 内部组成与机器字长
| 部件        | 里面存什么         | 通常与机器字长关系                        |
| --------- | ------------- | -------------------------------- |
| 通用寄存器 GPR | 数据、地址等        | **通常 = 机器字长**                    |
| PC        | 指令地址          | **通常 = 地址总线/地址空间所需位数，不一定等于机器字长** |
| MAR       | 主存地址          | **通常 = 地址线宽度，不一定等于机器字长**         |
| MDR       | 主存与 CPU 交换的数据 | **通常与数据总线宽度有关，不一定等于机器字长**        |
| IR        | 当前指令          | **通常 = 指令字长，不一定等于机器字长**          |
| ALU       | 运算数据          | **通常与机器字长相同或相近**                 |
| 标志寄存器     | ZF、CF、OF 等    | **通常远小于机器字长**                    |

数据看机器字长，地址看地址宽度，指令看指令长度，状态看状态位数

基本上只有 **ALU** 和**通用寄存器**跟机器字长相同

## 指令流水线

一条指令可能有：
取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB
如果没有流水线：
第一条：IF → ID → EX → MEM → WB
全部做完以后，第二条才开始。但是流水线：第一条做 ID 的时候，第二条可以做 IF。
于是：
第一条 EX
第二条 ID
第三条 IF
可以同时进行。

流水线的本质：
不同指令处于不同流水段，所以多个流水段在同一个时钟周期同时工作
把一条指令的执行过程划分成多个阶段，使不同指令的不同阶段在时间上重叠
### 流水线的 3 个重要问题：冒险
1. 结构冒险
硬件资源可能不够，比如两条指令想同时访问同一个存储器
2. 数据冒险
后面的指令可能需要前面指令的结果，但是前面的结果还没有产生（更准确的是：后面的指令依赖前面指令产生的数据，而前面的指令尚未把该数据写入后续阶段需要的位置）
比如：
`ADD R1, R2`
`SUB R3, R1`
第二条指令需要 R1，但是第一条还没写回，这就是数据冒险
3. 控制冒险
例如：
`beq` CPU 不知道到底：继续执行下一条，还是跳到另外一个地址。这就是控制冒险

结构冒险=资源冲突
数据冒险=数据依赖
控制冒险=分支跳转

### 流水线的性能计算

流水线主要提高吞吐率，而不是简单地减少单条指令的执行时间
假设：
5 个阶段，每阶段 1 个时钟周期
非流水：
5 条指令：5 × 5 = 25 个时钟周期
流水线：
第一条需要 5 个周期进入流水线，之后基本每个周期完成一条
所以 5 条大概需要：5+4=9个周期

一般形式：
**k 个阶段，n 条指令**
理想情况下：
**k + n - 1 个时钟周期**


## 中断
它解决的问题是：
CPU 正在执行程序的时候，如果突然发生一个需要处理的事件怎么办？

例如：
键盘输入来了
网卡收到数据
定时器到时间
设备请求 CPU

CPU 不需要一直傻等，而是：
正常执行程序
↓
发生中断请求
↓
CPU 响应中断
↓
保存现场
↓
找到中断服务程序（这个中断服务程序是请求中断的那个程序吗？答：不是，请求中断的是设备/事件，执行的是请求设备/事件对应的中断服务程序，被暂时打断的是原来正在运行的程序）
↓
执行中断服务程序
↓
恢复现场
↓
回到原程序继续执行

核心思想是：
中断 = 外部/内部事件主动请求 CPU 暂停当前程序，转去处理别的特定处理程序，不一定更紧急
中断是一种改变 CPU 正常执行流程、转而执行特定处理程序的机制
