
CPU 到底怎么知道“一条指令执行的时候，每一步该发出什么控制信号”？
比如执行：
ADD R1, R2

```
① 取指令
PC → MAR
M(MAR) → MDR
MDR → IR

② 分析指令
IR中的操作码 → 控制器

③ 执行 ADD
R1 → 某条总线
R2 → 某条总线
ALU 做加法
结果 → R1

```

每一步都需要控制信号

问题是：这些控制信号，到底有什么东西产生？

CPU 里有一个东西叫控制器 Control Unit，它的工作可以理解成：根据当前执行到哪条指令、当前处于哪个阶段，决定现在应该打开哪些开关。

例如 CPU 里可能有：
```
PC → MAR
MAR → 地址总线
内存 → MDR
MDR → IR
R1 → ALU
R2 → ALU
ALU → R1

```
这些数据通路本身不会自己动

控制器需要发送信号：
```
PC_out = 1
MAR_in = 1
MemRead = 1
MDR_in = 1
IR_in = 1
ALU_add = 1
R1_in = 1
...

```

所以可以把控制器想象成：CPU的总指挥

问题来了：
这个“总指挥”本身怎么产生这些控制信号？

# 硬布线：
用电路决定，根据指令+状态产生控制信号

例如：
```
如果：
操作码 = ADD
当前阶段 = 执行阶段

那么：
ALU执行加法
R1作为输入
R2作为输入
结果写回R1

```

这些“如果……那么……”最终全部被做成了**逻辑门、触发器、译码器等硬件电路**

所以叫：

> **硬布线控制**

因为控制逻辑是**直接硬件实现的**。

你可以把它理解成：

> **把“控制流程”焊死在电路里面。**


# 微程序


微程序：
ADD → 微程序A
SUB → 微程序B
MUL → 微程序C
DIV → 微程序D


**硬布线 = 控制逻辑由硬件电路实现**

**微程序 = 控制逻辑由存储起来的微指令实现**
