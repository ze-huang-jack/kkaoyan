### 数据寻址方式总结

基址寻址和变址寻址的公式都是EA=A+(寄存器)，但字段的含义刚好相反：

| 寻址方式 | 地址字段A   | 寄存器的内容       |
| ---- | ------- | ------------ |
| 变址寻址 | 首地址（固定） | 偏移量/数组下标（变化） |
| 基址寻址 | 偏移量（固定） | 程序基地址（变化）    |


> **核心目的：确定操作数（数据）在哪里。**
> 
> **永远记住一句话：**
> 
> **EA（Effective Address，有效地址） = CPU最终要访问的数据地址。**

| 寻址方式        | EA（有效地址）怎么算 | 数据在哪里        | CPU访问内存几次    | 最大特点      | 最适合什么场景             |
| ----------- | ----------- | ------------ | ------------ | --------- | ------------------- |
| **立即寻址**    | **没有EA**    | 数据就在指令里      | **0次**（取指除外） | 最快，不需要找地址 | 常数，如 `5`、`100`、`-1` |
| **直接寻址**    | EA=A        | 内存EA处        | 1次           | 最简单       | 已知固定地址的数据           |
| **间接寻址**    | EA=(A)      | 内存(内存A里的地址)处 | 2次           | 可以扩大寻址范围  | 指针、链表               |
| **寄存器寻址**   | 操作数就在寄存器    | 寄存器          | 0次           | 非常快       | CPU内部计算             |
| **寄存器间接寻址** | EA=(R)      | 内存(R里的地址)处   | 1次           | 地址放寄存器里   | 指针变量                |
| **相对寻址**    | EA=(PC)+A   | 内存EA处        | 1次           | 相对于当前位置   | 跳转指令                |
| **基址寻址**    | EA=(BR)+A   | 内存EA处        | 1次           | 程序可以整体搬家  | 程序重定位               |
| **变址寻址**    | EA=(IX)+A   | 内存EA处        | 1次           | 下标不断变化    | 数组、字符串              |

|寻址方式|一句话口诀|
|---|---|
|立即寻址|**数据就在指令里。**|
|直接寻址|**A 写哪，就去哪。**|
|间接寻址|**A 指向的地址才是真地址。**|
|寄存器寻址|**数据就在寄存器。**|
|寄存器间接寻址|**寄存器里放的是地址。**|
|相对寻址|**以 PC 为参照跳转。**|
|基址寻址|**改基址，不改代码。**|
|变址寻址|**改下标，不改首地址。**|

### RISC和CISC的区别
reduced instruction set computer 精简指令系统计算机
complex instruction set computer 复杂指令系统计算机

|          | CISC               | RISC                 |
| -------- | ------------------ | -------------------- |
| 指令系统     | 复杂、庞大              | 简单、精简                |
| 指令数目     | 一般大于200条           | 一般小于100条             |
| 指令字长     | 不固定                | 定长                   |
| 可访存指令    | 不加限制               | 只有LOAD/STORE指令       |
| 各种指令执行时间 | 相差较大               | 绝大多数在一个周期内完成         |
| 各种指令使用频率 | 相差很大               | 都比较常用                |
| 通用寄存器数量  | 较少                 | 较多                   |
| 目标代码     | 难以用优化编译生成高效的目标代码程序 | 采用优化的编译程序，生成代码较为高效   |
| 控制方式     | 大多数用微程序控制          | 绝大多数用组合逻辑控制，以硬布线控制为主 |
| 指令流水线    | 可以通过一定方式实现         | 必须实现                 |
## notes
1️⃣
一条指令是由什么组成的。核心是操作码+地址码
2️⃣
地址码不一定是内存地址，可能是寄存器、内存地址、立即数、偏移值。这就引出了寻址方式
1. 立即寻址
`mov r1, #10`
直接把数字 10 放到寄存器 r1 里，而不是把地址 10 的数据放到寄存器里，10本身就是我要的数据
2. 直接寻址
`load R1, 1000`
去内存地址 1000 找数据
EA=effective address = 1000
3. 间接寻址
`load R1,(1000)`
先去 1000 找一个地址，再去那个地址找真正的数据
例如`1000->5000->数据 42`
有效地址=5000，操作数=42
```
内存[1000]=5000
内存[5000]=42
```

1. 寄存器地址
`ADD R1, R2`
数据就在寄存器里，不用访问内存
2. 寄存器间接寻址
`LOAD R1, (R2)`
根据 R2 里面找一个地址，再去那个地址找真正的数据
R2->1000->数据43 （ R2 里存的地址就是有效地址）
那么，1000是有效地址
3. 基址寻址
EA = 基址寄存器 + 偏移量
例如 R1=10000, offset = 200
那么 EA=10200
例如一个数组：`arr[0],arr[1],arr[2].....`
可以用基址寻址来访问
R1 管“这一整块东西在哪里”，offset 管“我要这一块里的哪个位置”

4. 变址寻址
EA=地址+变址寄存器
典型用途：数组访问
比如 数组首地址=1000，下标 i=5
那么`arr[i]=1000 + 5 × 元素大小` （TODO这里数组访问，用基址寻址和变址寻址有什么不同）
更强调我要访问第几个元素

> **基址寻址强调“基地址 + 偏移”**

> **变址寻址强调“基地址 + 索引”**

基址：
“东西整体在哪里？” + “我要里面偏移多少？”

变址：
“东西从哪里开始？” + “我要第几个元素？”


4. 相对寻址
EA=PC + offset
例如 PC=1000，offset=200
那么目标地址=1200

3️⃣ 指令格式
一条指令里面，有几个操作数地址字段 （这个操作数是什么意思，操作码吗：看 TIPS)
例如
ADD R1, R2, R3
可以理解为：R1=R2+R3
三个地址：目的地址 R1，源操作数 R2, 源操作数 R3 (这里在暗示操作数是地址码吗：不是操作数和操作码是两回事)
这是三地址指令
**指令中有三个用于指定操作数位置的地址字段**

>[!tips]
>ADD       → 操作码
R1        → 地址码/地址字段 // 告诉 CPU 去哪里找
R2        → 地址码/地址字段 // R2=10, 10 就是操作数
R3        → 地址码/地址字段 
操作码=动词：做什么；操作数=名词：对谁做、操作的对象 

10、20    → 操作数
30        → 运算结果

4️⃣ 指令类型
数据传送类：LOAD, STORE, MOV
算数运算类：ADD, SUB, MUL, DIV
逻辑远算类：AND, OR, XOR, NOT
移位指令：SHL, SHR
转移指令：JMP, BEQ, BNE
重要的是不同指令改变了什么，访问了什么

5️⃣ 扩展操作码
指令长度=16bit
地址码=3个字段，每个 5bit
那么剩下的位数（实际上 16 - 15 =1 bit） 给操作码
但如果操作码采用扩展操作码编码似乎又不太一样了，但会计算就行

不同格式的指令，可以有不同数量的地址字段，有的指令需要 3 个地址字段、有的 2 个、有的 1 个、有的不需要，因此可以把原来属于地址字段的位置拿来扩展操作码

5️⃣ CISC RISC
CISC = Complex Instruction Set Computer 复杂指令集计算机
特点是指令很复杂，一条指令可以干很多事
还有：指令长度不固定

RISC = Reduced Iinstruction Set Computer 精简指令集计算机
特点是指令简单，CPU更容易高速执行（这句话是在说采用 RISC 的 CPU 速度比采用了 CISC 的 CPU 更快吗 : 并不是任何 RISC CPU 都一定比任何 CISC CPU 快 ）
还有：指令长度固定

```
CISC
指令格式规整
↓
译码简单
↓
数据通路简单
↓
更容易做流水线
↓
更容易提高吞吐率

```
RISC 的设计目标不是简单粗暴地“让 CPU 更快”，而是通过简化指令系统，使硬件实现和流水线优化更加容易
